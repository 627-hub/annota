# Annota 路线图 · 社交 / 差异化 / 导出（v0.1）

> 承接 [`product-spec.md`](product-spec.md) v1.2 与 [`implementation-plan.md`](implementation-plan.md) v0.2。
> 本文把「社交怎么做、跟谁不同、批量导出长什么样」三件事定下来，作为 R3/R4 的排期依据。
> **一句话结论：概念层（叠加可共享注释）已被 Hypothesis 做了十年；Annota 的缝是「视频画面区域 + 本地优先 + 学习闭环」，社交降级成小组共享 + 标准互通，不做通用社交网络。**

---

## 1. 竞争格局：三个结局

| 产品 | 做了什么 | 结局 / 教训 |
|---|---|---|
| **Genius**（前 Rap Genius，2009） | 逐句注解歌词 → 扩到音乐/诗歌/新闻；IQ 积分、verified 注解。峰值月访 25–30M，融资 ~$57M | **起来靠 SEO**：用户本就在搜「XX lyrics meaning」，它接住了这批搜索意图。2015 做「标注任意网页」插件没成；版权官司（NMPA）收场。→ 社交是结果，不是引擎 |
| **Hypothesis**（hypothes.is） | W3C Web Annotation 参考实现，开源（BSD-2），给网页/PDF/视频/图片加公共注释层。**现实走向：高教 B2B + LMS（Canvas/Blackboard/Moodle/D2L）**，300+ 院校 / 3M 标注者 / 95M 条 | 消费者级「标注整个互联网」没成；能活的形态是**组织者把一群人摁在同一材料上标**。→ 密度是被人为造出来的 |
| **Vidbolt**（水牛城，2014） | 「视频版 Twitter」：在视频**具体时间点**评论 + 时间轴热度色带。有收购意向 | **没了**（同名者已是无关 AI 工具）。→ 视频时间点评论的社交化，最像 Annota，也最像尸检台上那个 |

**三个结论**
1. 通用「内容之上的社交注释层」不是空白赛道，Hypothesis 占着且做得更深——**正面打必输**。
2. 消费者级开放社交网络在这类产品上反复失败；**密度必须由组织者/共同材料造出来**，不会自然涌现。
3. Genius 的增长红利是**现成搜索意图**；视频画面/时间点不是可索引文本，**别指望 SEO**，楔子靠渠道（学习群 / 小红书 / B站 + `../ielts-7.5` 存量用户）。

## 2. 差异化：Hypothesis 结构性地做不到的三件事（已核其官方文档）

| # | Annota 的配方 | Hypothesis 的现状 |
|---|---|---|
| 1 | **视频画面上的空间框选**（`t + box`：某一帧的某一块） | 视频注解 = **字幕文本层**，硬性要求「视频有 transcript」，只能选**字幕文字**加注，锚不到画面区域 |
| 2 | **本地优先 / 数据属于标注者 / 无账号可带走** | 服务端账号 + LMS 托管，架构与商业模式决定它不做「你自己的文件」 |
| 3 | **语言学习 → SRS 闭环**（画面语境 → 生词 → Anki/JEV head） | 是「批判性阅读」教育工具，不是学习产品 |

> 图片矩形框 Hypothesis 2025 才补，且**限 PDF**（网页图片/自由选区仍标 "coming soon"）——Annota 的 R2 图片框比它这一步还靠前一点。

**横切策略：不跟它对立，做互通。** Annota 本就对齐 W3C Web Annotation，应能**导入/导出** Hypothesis 及标准格式，接它的生态而非重造一个它。

## 3. 四层清单（把功能归位，避免全塞一起做）

> 判据：**护城河早做 / 密度引擎是主线 / 社交机制有密度才做 / AI 押后。**

### L1 护城河（画面区域 + 本地优先 + 学习）— 早做
- 标注工具框（视频画面区域框）— 核心差异化
- 视频跳转点 / 时间轴锚
- 视频 shot/take 分割（镜头边界）
- **AI 批量对齐：从标注起点向两端对齐镜头** ← R4→R5 的桥（同时改善标注质量 + 产训练样本）
- **批量导出**：标注时点截图（仅本标注文本+热力框）+ 词汇/句子要素 → Anki 牌组 / CSV / JSONL
- 本地存储 / 无账号可用 / 一键导出即走
- 轻量化分类模型（JEV 式 word↔region head）— 最后，依赖数据量

### L2 密度引擎（让同一内容上有人）— 主线，最容易被漏
- **共同片单 ContentList**（同一套听力/网课/合集）
- **组织者角色**（老师/群主/up主：建组 → 钉片单 → 拉人）
- 轻量注册登录（**可选**：本地不登录照用，登录只为入组/署名/发布）
- public / private group + tag
- 标注可同步列表（组内共享）
- **组页 permalink**（公开可访问、可分享、可被收录）— 增长回路

### L3 社交机制（有密度后才做，别做全局榜）
- 赞踩
- 点数 / IQ（防刷 + 审核配套）
- 关注 / 发现 / 热门（跨组）

### L4 AI（押后，见 implementation-plan R3b）
- AI 引导词自定义
- `/suggest` AI 找词
- agent loop 增强

### 横切
- W3C 标准互通（Hypothesis 导入/导出）

## 4. 分期

| 期 | 内容 | 依赖 | 验收 |
|---|---|---|---|
| **R3a 数据可见 + 学习闭环**（非 AI） | 数据工作台 `/console`；通用批注/自定义 tag（spec 8.3 A）；**批量导出** | 现有 R1/R2 | 一键从一条标注导出带截图的 Anki 卡；工作台出训练集 JSONL |
| **R3b AI 协作**（押后） | `/suggest` + AI 辅助建议 + agent loop 增强 + AI 引导词自定义 | 模型选型（spec §16 #4）+ 数据基线 | Recall@5 达标；确认率 ≥50% |
| **R4a 私组** | 私密 Group + 共同片单 + 组内同步列表 + 组页（私密） | 本地服务 + 同步 | 两人同组，各自标注在组页可见 |
| **R4b 公开组页 + 互通** | 轻账号 + public/private tag + 公开组页 permalink + W3C 导入导出 | 轻后端 + 身份 | 公开组页可分享、可被外部标准工具导入 |
| **R4c 镜头对齐** | shot/take 分割 + 从标注点向两端对齐镜头 + 计数器 | 边播边算的帧采样 | 标注自动获得镜头长度的片段 |
| **R4d 社交机制** | 赞踩 / 点数 / 关注 / 热门 | 已有密度 | 组内互动发生；跨组发现可用 |
| **R5 模型** | JEV 式 head 训练/评测 | 数据积累 | 模型卡发布 |

> R4a/R4b 的核心对象是 **Group**，不是 Follow 图——比开放社交网络轻得多，也活得下来。

## 5. 批量导出规格（本轮新增）

**目标**：把一个标注文件（媒体 / Pack / 片单）里的视频标注，逐条导出成**可复习的卡**——截图 + 词汇/句子要素，输出 Anki 牌组等。

**卡片结构**
- **正面**：该标注时点 `t` 的**视频画面截图**，图上**仅叠加本条标注**的**热力框 + 文本**（不画其他标注、不带 UI 元素）。
- **背面**：词汇 / 句子要素——`word`、`label`（释义）、`pos`/tags、来源（平台 + 标题 + 时间码 + 链接）；音标/音频由下游 `../ielts-7.5` 提供则附。
- **元数据**：deck 名（按媒体/片单/Pack）、tags、`source URL + t`（回看那一帧）。

**格式**：Anki `.apkg`（主）/ CSV / JSON / 训练集 JSONL（对齐 spec §9.2）。

**实现要点**
- 截图来源：Tauri `capture_frame(t)`（wry screenshot）或 canvas 取帧；跨域 taint 走 `captureVisibleTab` / 壳通道（不用 `drawImage`）。
- **只叠加本条的框 + 文本**：需要 `renderOnly(entry)` 渲染能力（现 showAll 是全部显示）。
- **截帧时序**：`seek(t)` → 等 `seeked` + `requestVideoFrameCallback` → 再截，避免截到旧帧。
- **批量**：逐条 seek→截→叠→存；长视频 1000 条要能中断/续跑 + 进度。
- **生成**：本仓库标准库写出器 `app/service/anki_export.py`（zipfile+sqlite3，零依赖，产出与 genanki 对齐）；截图作媒体文件嵌入。
  （注：`../ielts-7.5/app/vocab/lib/anki.py` 是 AnkiConnect 客户端、**不产 .apkg**；genanki 参考见 `../ielts-7.5/assets/vocab/build_anki.py`。）

**合规边界（重要）**
- **共享 Pack 不含截图**，仍是纯标注 JSON；
- 截图只进**用户本地的个人导出**（自己的 Anki 库），属用户自持衍生品，不公开分发。

## 6. 关键决策点（R4 前要拍）

| # | 决策 | 倾向 |
|---|---|---|
| S1 | 后端形态 | 先静态 Feed + 组页；真实需求（跨网/公共池）出现再加**无状态对象存储**（不建媒体云） |
| S2 | 身份与同步 | ✅ 定（[`architecture.md`](architecture.md)）：**云默认 / 本地兜底 / 公开可匿名读**；轻账号为默认同步身份，本地密钥保持单机可用 |
| S3 | shot 检测实现 | 不搬媒体 → **边播边 canvas 采帧**，按需/缓存镜头边界；非一次性批处理 |
| S4 | 互通格式 | W3C Web Annotation 导入/导出（对接 Hypothesis） |
| S5 | 密度起点 | 先一个高密度垂直群（IELTS/TOEFL，接 `../ielts-7.5`），不做泛社交 |
