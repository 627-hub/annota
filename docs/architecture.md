# Annota 架构说明与决策记录（architecture.md v0.1）

> 承接 [`product-spec.md`](product-spec.md) v1.2、[`roadmap.md`](roadmap.md)、[`implementation-plan.md`](implementation-plan.md) v0.2。
> 本文只定**架构接缝**：服务端分层 / 同步 / 身份 / 公开页 / 渲染复用。**不改数据模型与 core 逻辑。**

---

## 0. 一句话结论

**核心不重构。** 新增「托管服务」作为**第二部署目标**，与现有本地服务**共用同一 API 契约 + W3C 数据模型**；
同步分层为「**云默认 / 本地兜底 / 公开可匿名读**」，本地服务降级为 fallback（不取消）。

---

## 1. 部署分层

```
                    ┌─────────────── 客户端 ───────────────┐
                    │ Tauri 浏览器 / MV3 扩展 / userscript  │
                    │  注入 core.js（overlay）+ 页面态 UI    │
                    └───────────────┬──────────────────────┘
                                    │ 同一接口（可指向不同 server）
                    ┌───────────────┴───────────────┐
                    ▼                               ▼
          [本地服务 · fallback]              [托管服务 · 默认]
          回环 8793 / 单人 / 无鉴权          账号 / 组 / 公开页 / 跨网
          = 离线模式 + 兜底通道              = 多端同步 + 协作 + 发布
```

- **本地服务**：保留现有能力（标注、截图、MCP、`/api/anno` 同步），定位从"主同步"**降为离线模式 + 兜底通道**，不再加投入。
- **托管服务**（新）：承载轻账号、Group、共同片单、公开组页、跨网多端同步。**静态优先**，真实需求出现再加无状态对象存储（**不建媒体云**）。
- 客户端**只面向"一个 server 接口"**，运行时可指向本地或托管——这是必须现在定死的接缝。

## 2. 决策记录（ADR）

| # | 决策 | 理由 |
|---|---|---|
| **ADR-1** | 本地服务与托管服务分**两个部署目标**，共用同一 API 契约 + W3C 数据模型 | 避免把账号/组/公开页硬塞进单人回环服务，导致以后无法拆分 |
| **ADR-2** | 同步分层：**云默认 / 本地兜底 / 公开可匿名读**；默认匿名、**登录绑定高意愿动作**（§4） | 云是跨端最好用路径；分享链接打开不能要登录（否则砸传播回路）；但注册要发生在"用户本就想做点什么"之时，挂在门口只会劝退高意愿的人 |
| **ADR-3** | 身份 = 可插拔 `identity` 模块：**本地密钥对先行**（单机署名/校验），**轻账号**（昵称+头像）为默认同步身份 | schema 已有 `creator` + `va:sig`；账号只为入组/署名/同步，不拦浏览 |
| **ADR-4** | **公开页 = 同一 overlay 渲染层的第二部署**（免登录可看） | 复用现有观看端概念（spec P3）；公开可看才有增长回路（Genius/Hypothesis 的共性） |
| **ADR-5** | 服务端对象模型 `Group / ContentList / Member` 建在**托管服务**上 | 小组共享是密度引擎；本地服务不管这些 |
| **ADR-6** | **批量导出在本地完成**（截帧/叠框/生成 Anki）；公开共享**仍为纯标注 JSON** | 合规：共享 Pack 不含截图，截图只进用户本地个人导出 |

## 3. 影响矩阵

| 功能 | 现有基础 | 影响 | 类型 |
|---|---|---|---|
| 批量导出（截图卡→Anki） | Tauri `capture_frame` / MCP 已有；entry 是 W3C | 前端加 `renderOnly(entry)` + seek 稳定后截帧；`.apkg` 由 `app/service/anki_export.py`（标准库，零依赖）生成 | **加法 + 1 处小改** |
| shot 分割 / 从标注点对齐镜头 | 无 | 新增前端帧采样模块（边播边算） | **加法**（新模块） |
| 轻账号 | schema 有 `creator`+`va:sig` | 新增 `identity` 模块 + 托管端 | **加法**（新组件） |
| Group + 共同片单 + 组页 | `Pack/Feed/AnnotationCollection` 已有；观看端概念已有 | 新增服务端对象 + 页面态路由 | **加法**（后端 + 页面） |
| 公开片单页 / 免装观看 | 观看端 overlay 概念（spec P3） | 同一 overlay 跑在托管 web（第二部署） | **加法**（同渲染栈） |
| W3C 互通 | 数据模型本身即 W3C | 加 import/export 映射 | **加法** |
| AI（R3b） | MCP/agent 脚手架 R1 已有 | 推后 | **不动** |

## 4. 两条改造（局部）

1. **overlay 渲染**：`showAll` → `renderOnly(entry)`。用于批量导出时"只画本条框+文本"。走 `build.py` 同源纪律，不动逻辑。
2. **服务端抽象**：把现有回环服务抽象成"一个 server 接口"，客户端可指向本地或托管（ADR-1）。

**不动的**：数据模型、core 逻辑、三形态打包、MCP 工具契约、现有同步 API 契约。

**三条底线（ADR-2）**：
1. 单机**不注册也能用**全部核心功能（离线标注 + 文件导出/导入）；
2. **分享链接 / 公开页打开不要求登录**（匿名可读）——唯一硬底线，否则链接一传播就死；
3. 数据随时可导出、可自持、可互换——**不锁死**。

**登录边界（ADR-2）**：默认匿名可读、无硬墙；**登录绑定高意愿动作**，把注册放在"用户本就想做点什么"的那一刻。

| 动作 | 要登录吗 |
|---|---|
| 打开分享链接 / 公开页 / 发现页浏览 | **不要**（硬底线） |
| 滚动看别人的标注 / 词卡 | 不要 |
| 自己在本机标注 | 不要（本地优先） |
| 收藏 / 收下牌组进"我的库" | **要** |
| 订阅片单 / 关注作者 / 评论 / 赞踩 | **要** |
| 加入组 / 看组内私有内容 | **要** |
| 多端同步 / 发布 / 署名 | **要** |

> 阅读者注册率天然只有个位数——**不需要他们全登录**。密度靠的是"会为收下牌组/加入片单而注册"的标注者与组员；硬墙不会把读者变用户，只会把他们变逃客。
> 按内容类型分层：**公开页/分享链接** 匿名可读 → **组内容** 入组才可读 → **个人库/多端** 登录。

## 5. 边界与合规

- 不搬媒体；公开组页用**官方 iframe** 嵌视频；公开的是**短标注**，不导出字幕/正文原文。
- 公开 UGC 需配**举报 / 私密开关**；注册只用于高意愿动作（收下/订阅/关注/评论/入组/同步/发布），**不拦浏览**。
- 托管服务只存标注与笔记产物；遥测默认关。

## 6. 未决

- 托管服务的静态/动态边界（组页静态优先；成员写操作何时需要动态端）。
- 本地服务在 UI 上的暴露程度（隐藏为"离线模式"还是保留"局域网同步"入口）。
- 公开页的 renderer 与注入态 overlay 的代码复用程度（共享多少渲染代码）。
